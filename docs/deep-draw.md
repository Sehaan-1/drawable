### Product

Continue the implementation in the existing drawable repository, without copying, modifying, or importing Clippy code or assets. The product is a local Linux web application that retrieves existing character-related line-art references while an artist draws. Internet access is permitted for explicit setup/download steps; inference, search, training, preferences, and drawing run without network services afterward. No paid APIs, hosted databases, subscriptions, or service charges are required.

Required behavior:

- A pressure-sensitive canvas with four drawing layers and one separate reference trace layer.
- Automatic search after a completed content change and 350 ms without further drawing.
- Recognition of visible character details, heads, hair, limbs, figures, and compositions, including incomplete drawings.
- Same/near-viewpoint structural matching for identifiable eye queries: perspective, foreshortening, contour relationships, and visible orientation matter more than merely matching the subject or preferred style. Apply the same usefulness principle to other scopes where the drawing provides sufficient evidence; certify their coverage separately.
- Five styles: manga/anime, Western comic/ink, realistic/academic, cartoon, gesture/sketch.
- Best Match first; explicit and learned style preferences reorder style rows only.
- Native line art preferred; reviewed extracted line art permitted and labeled.
- SFW results, local persistence, pinning, tracing, and PNG/SVG export.
- Lossless editable `.drawable` project export/import, plus bounded PNG and self-contained SVG sketch import as flattened raster artwork. An imported sketch opens as an independent document and never replaces the active drawing.
- CPU fallback when CUDA is unavailable, with degraded performance/features reported.

Non-goals: generation, color painting, lasso/region retrieval, visible photographic references, arbitrary objects/animals/scenery, accounts, collaboration, cloud sync, public hosting, desktop packaging, and redistribution of restricted datasets. There is no artificial drawing-person-count limit. Pose matching processes at most eight people; for larger compositions it is unavailable and image/structure retrieval continues.

### Viewpoint-aware usefulness and uncertainty

For an eye drawn in three-quarter perspective, a front-facing eye is not automatically useful merely because both references depict an eye. Prefer references whose observable structure would help the artist continue that drawing. "Same" and "near" mean reviewed compatibility of the visible perspective and geometry, not pixel identity, a shared coarse label alone, or a recovered exact 3D angle.

Keep viewing perspective (front/three-quarter/profile and above/level/below), image-plane tilt, and pupil gaze separate. A tilted frontal eye is not necessarily a three-quarter eye, and a pupil looking sideways does not prove that the head is in profile. Preserve image-facing direction; do not silently mirror an asymmetric reference to claim a match. Gaze and expression may be recorded as optional refinement attributes, but this amendment does not introduce a separately certified gaze-matching feature.

Infer query attributes only from the current visible drawing. An isolated curve or incomplete eye may support several interpretations; do not borrow the final drawing, an assigned reference's labels, or the artist's unobserved intention. Subject confidence and viewpoint confidence are separate. Unknown viewpoint does not mean unknown subject, poor artwork, or an automatic negative example. Existing scope groups and the whole-canvas retrieval contract remain intact; this does not add lasso retrieval, 3D reconstruction, or image generation.

The operational contract is best available structurally compatible references, with honest tentative/experimental presentation when the evidence is weak. It is not a guarantee that every drawn perspective has an exact counterpart in the gallery. Section 5's viewpoint review contract, section 7's ranking rules, and section 9's viewpoint evaluation define how this requirement becomes measurable.

## 4. Canvas and live-search behavior

### Document and input

Use a fixed 2048 × 2048 logical canvas, four stable drawing-layer IDs, and one trace slot. Defaults: Layer 1–4 visible at opacity 1, Layer 1 active. View transforms never change stored points. Clip rendering/retrieval to the canvas while pointer capture continues receiving outside samples.

The versioned document stores UUID, layer order/visibility/opacity/names, committed operations, trace transform/asset/opacity/visibility, tools, viewport, and undo metadata. `DrawingOperation` is the tagged union `StrokeOperation | RasterOperation`. Stroke operations store ID, layer ID, global sequence, raw `(x,y,pressure,t_ms)` points, pressure/time availability, pointer type, optional tilt, brush options, and renderer version. Time is monotonic relative milliseconds; stroke boundaries define pen state. A raster operation stores a stable ID, `kind: raster`, content-addressed asset ID, logical-canvas `x`, `y`, `width`, `height`, and creation time. The visible canvas, worker, and export use shared pure geometry/operation code.

Keep three versions distinct: the IndexedDB record schema version, the internal drawing-document schema version, and the portable `.drawable` format version. The current IndexedDB record and `.drawable` format are versioned, but the embedded drawing payload is not; introduce an explicit internal document schema plus migration from the current payload before M2. The current stroke payload also lacks global sequence, layer ID on the operation, device/availability flags, tilt, and renderer version. Those are known migration work, not grounds to delete the target fields.

Use pointer capture and coalesced events when supported. Predicted points are visual-only. Pen pressure is normalized 0–1; mouse input commonly has constant active pressure. Provide Auto/Real/Simulated pressure settings; do not infer support from a nonzero value alone. [MDN pressure documentation](https://developer.mozilla.org/en-US/docs/Web/API/PointerEvent/pressure)

Mouse left-button and pen draw. Pen suppresses touch while active. Touch is navigation only: two-finger pan/pinch. Space+drag and middle-button drag pan. `pointercancel`, lost capture, blur, or Esc cancels uncommitted ink without an undo command. Editable fields consume their normal shortcuts.

Keep high-frequency points outside React component state. Draw with requestAnimationFrame over cached committed layer surfaces; rebuild changed layers only. Send ordered committed deltas/acknowledgments to the worker, not the full document per sample. Supported Chrome/Edge use OffscreenCanvas; feature-detect and label a slower fallback for other browsers. [MDN OffscreenCanvas](https://developer.mozilla.org/en-US/docs/Web/API/OffscreenCanvas)

### Tools and history

- Pressure brush: size 12 logical px, thinning 0.65, stabilization 50, start round cap, end taper 8 px. Mouse simulates pressure; pressure-capable pens use real pressure.
- Stabilization `s` in 0–100 maps to smoothing `0.10 + 0.009*s` and streamline `0.009*s` (defaults 0.55/0.45). Store options per stroke. Slider changes affect future strokes only.
- Monoline: thinning 0, round caps, no end taper, current size. Brush/eraser size range 1–40 logical px.
- Zoom 10–800%, centered on cursor for wheel/pinch; fit centers the full canvas with padding.
- Eraser: constant-width circular vector path that removes earlier ink on the active layer in command order. It never paints white, erases other layers, or erases future strokes.
- Undo includes ink, erases, clear, layer-property edits, and trace edits. A drag is one command; tools/view navigation are not undoable. Keep 500 undoable commands. Eviction advances the history baseline without deleting older artwork; new edits clear redo.
- Trace: one slot behind drawing layers, opacity 0.3 by default, translate/scale with aspect ratio preserved, visibility/opacity controls. Trace action replaces the slot as an undoable edit. No rotation in v1. The current scaffold supports scale but not translation; translation remains required before the complete canvas claim.
- PNG: 2048 × 2048, visible user layers/opacity, white or transparent background. SVG: same viewBox/geometry, chronological erase masks that affect earlier content only. Both always exclude trace and hidden layers.

perfect-freehand supports these stroke options; nonzero taper takes precedence over the endpoint cap. [Official documentation](https://github.com/steveruizok/perfect-freehand)

Shortcuts: B pressure, M monoline, E eraser, [ / ] size by one px, Ctrl/Cmd+Z undo, Ctrl/Cmd+Shift+Z or Ctrl/Cmd+Y redo, Space pan, 0 fit, + / - zoom, 1–4 active layer, H trace visibility, Esc cancel stroke/modal. Provide accessible button labels, visible keyboard focus, and restrained status announcements.

### Portable projects and sketch import

`.drawable` format version 1 is an accepted public interface. Its MIME type is `application/vnd.drawable.project+json`; the top level contains `format: drawable-project`, `formatVersion`, application version, ISO export time, portable document, active layer ID, and embedded assets. A project is at most 50 MiB and contains exactly the four stable layer IDs, unique layer/operation IDs, at most 10,000 operations, and at most 1,000,000 raw points. It preserves editable strokes, erasers, raster operations, layer properties, active layer, and trace metadata. It does not embed trace reference pixels; an asset ID may be retained only as metadata and resolves subject to the active gallery's permissions and availability.

Embedded project assets are normalized PNG only. Each includes ID, MIME type, dimensions, byte length, lowercase SHA-256, and base64 data. Its ID is exactly `raster-{sha256}`. Reject missing, duplicate, mismatched, corrupt, oversized, and unreferenced assets. Validate the complete project and every embedded checksum before storing or activating anything. Reject unsupported older versions and give a specific “created by a newer version” error for a greater numeric version. Failure is atomic and never mutates the active tab or leaves partially materialized document state.

PNG sketch import accepts at most 25 MiB; self-contained SVG accepts at most 5 MiB. Both allow at most 8,192 pixels on either decoded edge and 40,000,000 decoded pixels. Validate PNG signature and header dimensions before full decode. SVG rejects document types/entities, scripts, `foreignObject`, iframes/objects/embeds, images/audio/video, style and animation elements, event attributes, inline style, source attributes, and non-fragment `href` or `url(...)` references. Parse successfully before decode.

Normalize an accepted PNG/SVG to a content-addressed PNG on the 2048 × 2048 logical canvas, fitting it proportionally and centering it. Create an independent document with the raster on `layer-4`, name that layer “Imported sketch,” and leave `layer-1` active. Stage the document and assets in IndexedDB behind an unguessable token with a 30-minute lifetime; the explicit open action atomically consumes the token and creates a new tab and new document ID. Import never overwrites the source tab. Syntactic file safety is not line-art suitability: before pilot readiness, the import path must implement section 7's explicit normalization or rejection of unsupported photographic and light-on-dark input.

PNG and SVG exports composite visible vector and raster artwork with layer opacity and chronological erasing. SVG embeds referenced normalized raster PNGs as data URLs and applies later erasers through masks. Hidden layers and trace content remain excluded from both visual formats. `.drawable` is the lossless editable exchange format; PNG/SVG imports are intentionally flattened raster operations rather than reconstructed vectors.

### Autosave and capacity

Debounce an IndexedDB transaction by 500 ms after committed edits. Store schema/checksum/generation and retain the previous valid generation. Visibility-change flushing is best-effort; never rely on unload completing async writes. Persist complete artwork and referenced raster assets separately from the bounded undo history. Reload prompts to restore or start new, preserving the old backup until another successful save.

One writer tab owns each document using `navigator.locks`, with BroadcastChannel coordination when locks are unavailable. If another tab already owns the document, automatically fork an independent copy with a new document UUID and a clear notice; never let two tabs silently write the same document. Every activated tab gets a new search-session UUID, even after document restore or import. Quota/write failures display an unsaved warning and preserve live export. Corrupt records are retained; load the previous valid generation or a blank document with recovery information.

Support up to 10,000 draw/erase operations and 1,000,000 raw points per document. Never silently discard artwork. At capacity, stop accepting additional ink with a warning and allow export/new document. Benchmark normal drawing using section 2's fixture; verify capacity boundaries separately.

Current persistence and worker debt is explicit: autosave records lack the planned document checksum; corrupt-record validation/recovery is incomplete; capacity limits are validated during project import but not enforced while drawing; a successfully materialized staged-import token is not yet deleted; imported raster assets lack a final lifecycle/garbage-collection policy; fixture pins use `localStorage` rather than the planned persistence API; the snapshot worker receives the full document instead of ordered deltas/acknowledgments; and mixed vector/raster parity across visible canvas, worker, PNG, and SVG has not passed the required suite. Preserve referenced assets until a safe reference-aware cleanup policy exists. The ordered-delta architecture remains the performance/capacity target.

### Raster/stroke consistency

Retrieval uses the composited visible user ink after opacity/erases, on white. The worker produces a 512 × 512 PNG and the exact revision/generation that generated it. Trace is always excluded.

Visible raster operations participate in the raster/structural snapshot. They do not become invented vector tokens. If any visible nonzero-opacity layer contains an active raster operation, disable the stroke branch with `stroke_status=raster_content` because the transported stroke sequence does not describe all visible content; image/structure retrieval continues. Hiding, clearing, or undoing the raster operation may restore eligibility. Imported raster artwork remains browser-local and never becomes gallery or training data without a separate explicit consent and rights record.

Otherwise the stroke branch uses committed vector strokes from visible nonzero-opacity layers, ordered by global sequence, with feature-availability flags and layer opacity. Exclude hidden/cleared/undone strokes. If an included layer has any active erase operation, unsupported geometric transform, or a raw path outside the logical canvas, disable the stroke branch for that query. Clamping outside vertices independently can create false ink along the boundary and is forbidden. Undo may restore availability. Deriving partially erased vector fragments is deferred; image/structure retrieval continues. Train with matching branch-dropout/opacity cases.

Normalize/simplify eligible strokes in the worker with section 6's versioned recipe, sending <= 1,024 tokens rather than unlimited raw history. Keep raw source stroke/point counts separate from token count. These counts mean active vector draw/erase operations and raw samples in visible nonzero-opacity layers after undo/clear, before subtracting erases or clipping outside paths; raster operations count toward document capacity but never toward `stroke_count`, `point_count`, or stroke tokens. Send a `counts_approximate` flag when erasing or outside paths make them differ from visible ink; the ranker receives that mask. Counts are diagnostics/features, not proof of pixel visibility. Overall insufficiency is raster-based, independent of device sampling: on the 512 image, ink is grayscale < 245; insufficient means < 8 ink pixels OR ink-bounding-box diagonal < 3 pixels. These are bootstrap values to validate/freeze during pilot work. Stroke activation additionally needs one complete stroke and >= 20 normalized tokens. A visible simple curve can therefore yield image-based provisional results.

### Search state machine

`canvas_revision` advances on committed retrieval-visible document changes. `query_generation` advances whenever a response is invalidated, including drawing pointerdown and text changes. Both are monotonic JavaScript-safe integers in the current runtime session, never restored from old sessions.

Document activation, restore, fork, and import create a fresh `session_id`, invalidate every older request/worker result, and establish a new revision/generation tuple. Adding, removing, hiding, reordering, or changing the opacity of visible raster content is retrieval-visible and advances revision/generation. The current fixture frontend has revision/generation checks but no complete session-ID contract; complete that in M1.

1. Drawing pointerdown immediately advances generation, aborts the request, cancels debounce, and invalidates pending worker output. Prior cards may stay marked as belonging to the previous drawing state; no response applies while drawing.
2. Committed stroke/erase/undo/redo/restore/clear or visible layer visibility/opacity/order changes advance revision and generation and start the 350 ms idle timer. Rename, active-layer choice, tools, zoom/pan, trace, pins, and style-row reorder do not trigger retrieval.
3. Text changes advance generation, keep canvas revision, and debounce 350 ms after drawing stops. Normalize whitespace and limit to 120 Unicode code points. Explicit style changes only reorder existing groups.
4. When idle, request a worker snapshot for `(session_id, canvas_revision, query_generation)`. Discard mismatched replies. Submit one current payload.
5. Apply results only if all three identifiers match and no stroke is active. A request captures one gallery build; never mix result cards from different builds in one response.
6. A cancelled stroke still invalidated old responses; schedule a fresh query if the displayed tuple is no longer current. Pure pan does not invalidate.

Blank/clear/insufficient input immediately clears dynamic groups and shows “Keep drawing—there is not enough information yet”; pins remain. Loading retains prior results with an indicator. Failure preserves them labeled “Previous results” with Retry. Retry uses a new generation; no automatic retry of obsolete requests.

### Reference panel

Use a compact tool rail, central canvas, and 400–460 px desktop panel; below 1100 px make the panel collapsible. Include interpretation, text hint, style chips, results, and pins. Cards show thumbnail, style, native/extracted status, match label, and Open/Pin/Trace. Open displays a local full-resolution viewer with accessible provenance/terms/attribution.

Confident: Best Match <= 8, followed by five style rows <= 6 each. Empty style rows say there are no relevant matches. Never lower the floor to fill a row. An asset may appear in Best Match and its style row, but no duplicates within a row. Provisional: replace Best Match/style rows with <= 3 known-scope interpretation groups of <= 4 results; keep pins. No unknown group. Say “Tentative”; percentages require validated calibration.

Explicit style goes immediately after Best Match. Remaining rows use learned affinity, ties resolved manga, realistic, Western comic, cartoon, gesture. Disabled learning uses that fixed order. Provisional groups use scope order and ignore style preference.

Curated progression scenario: ambiguous curve -> possible eye/eyebrow/mouth; eyelid plus corner/iris -> eye; added facial structure -> head; multiple figures -> composition. These are validated scenario tests, not guaranteed interpretations of every arbitrary curve. Whole-canvas retrieval changes scope as content grows.

Add viewpoint scenarios to that progression: a clear three-quarter eye should favor useful three-quarter/nearby references over reviewed incompatible frontal/profile distractors; a changed head orientation should update results from the current pixels; and ambiguous eye-only prefixes should not acquire a fabricated angle. A confidently identified subject can still have tentative viewpoint evidence. Use qualitative match wording; show "same/near angle" only for a feature profile with supporting validation, never solely from a scope label or embedding cosine. When no structurally relevant candidate survives, retain the existing no-relevant-results behavior rather than fill rows with wrong-angle images. Trace remains excluded from query pixels, and trace rotation remains out of scope in v1.

### Viewpoint data and review contract

Use a separately versioned viewpoint label snapshot for applicable reference assets and visible query prefixes. Initial review vocabulary is horizontal view `front`, `three_quarter`, `profile`, `rear`, or `indeterminate`; image-facing direction `image_left`, `image_right`, `center`, or `indeterminate`; and elevation `level`, `view_from_above`, `view_from_below`, or `indeterminate`. These are qualitative observations, not measured 3D yaw/pitch. Record each axis independently so partial knowledge is retained. Anatomical left/right, if known, is a separate observation and must not be confused with image-facing direction. Optional signed image-plane tilt estimates need an explicit coordinate convention and evidence; they never become camera-angle ground truth.

Store annotation schema/rubric version, asset or prefix ID and image checksum, review state (`unreviewed`, `reviewed`, or `not_applicable`), pseudonymous reviewer, review time, and evidence basis (`visible_crop` or `crop_with_parent_context` for references; `visible_prefix` for queries). A reviewed indeterminate value means the image was examined but does not establish that axis; an absent/unreviewed value means no accepted judgment exists. Ambiguous query prefixes may have a reviewed acceptable-view set. Do not force viewpoint annotations onto scopes/images where they are not applicable.

Preserve parent asset ID, reviewed crop rectangle, and the permitted original/head-context link. Reference reviewers may use recorded parent context to establish a crop's provenance and perspective; query reviewers see only the visible prefix when labeling its perspective. Context does not recover a query's future intention. Do not invent missing eye geometry from a parent or accept an over-tight crop merely because the parent has a known angle. Any additional context crop is a separately rights-checked derivative in the same source/split/duplicate family.

For each applicable reviewed query/reference pair, store `view_match: same | near | incompatible | indeterminate | not_applicable`, its rubric version, reviewer, and concise reason separately from the existing usefulness grade 0–3. "Same" requires compatible observable perspective and orientation; equal bucket names alone are insufficient. "Near" requires useful geometry despite an observable difference, not an automatic adjacency rule between buckets. The versioned rubric includes accepted/rejected examples of foreshortening, visible corners/lids, facing direction, and context ambiguity. Freeze the initial rubric before the pilot judgment batch; revisions create a new snapshot and require consistent re-review of affected labels.

These are normative data interfaces. The shared `drawable-research-contracts` package now implements strict, versioned asset-viewpoint and pairwise view-match records; the curation API persists human asset-viewpoint labels and review-only snapshots include the rubric identity/hash. Existing legacy catalog rows with no label remain unreviewed. A query-prefix label schema/workflow, viewpoint coverage report, and ML manifest/bundle compatibility are still absent. No migration silently approves labels or changes learning splits. Keep the public `.drawable` v1 format and raw recorder consent semantics unchanged: viewpoint review is derived research metadata, not implicit recording consent.

### Ingestion and extraction

Run resumable, idempotent stages keyed by input checksum plus pipeline version:

1. Validate decoder, maximum pixels (40 megapixels), EXIF orientation, and original short edge >= 256 px. Decompression-bomb warnings are failures. Retain originals unchanged and store normalized derivatives separately.
2. Deduplicate exact bytes. Normalize grayscale/white background for analysis. Quarantine blank (<1% meaningful ink) or dense (>45% dark pixels) images for review; detail crops may have different reviewed thresholds. These candidate filters do not apply to incomplete user queries.
3. Quarantine explicit/suggestive/uncertain source ratings and run a local SFW classifier. Use manual review for disagreement. Default visible policy excludes explicit nudity and sexual content, including artistic figure studies; covered/neutral anatomical detail studies are allowed.
4. Detect text with PaddleOCR. Use provided text/balloon masks where present. More than 5% OCR area after masking, watermark, clipped anatomy, dominant panel borders, or damaged extraction goes to review/rejection. Record all thresholds in the build recipe; native text-free artwork is preferred.
5. Generate annotated crops, line extractions, thumbnails, quality features, and duplicate proposals. Never accept a crop because a detector merely produced a box.
6. Duplicate proposals are the union of perceptual-hash distance <= 6 and MobileCLIP cosine >= 0.985; do not require both as the only candidate path. Confirm automatic duplicate removal when both pass, or route single-signal cases to review. Shared-source variants are always grouped. Keep the highest reviewed quality, then resolution, then stable-ID tie-break. Similar pose alone is not duplication.

Prefer native line art. Anime2Sketch is the initial manga/cartoon extractor; Informative Drawings the initial realistic-art extractor. Pin exact weight variant/checksum and test representative output before adopting either. Their published setup environments are not a tested modern API dependency set. Run extraction separately; Canny is auxiliary training/baseline input only, never visible reference art. [Anime2Sketch](https://github.com/Mukosame/Anime2Sketch), [Informative Drawings](https://github.com/carolineec/informative-drawings)

OpenNSFW2 and PaddleOCR add other frameworks; isolate them in offline ingestion environments/processes, preferring CPU so they do not contend with serving. Cache their weights too. [OpenNSFW2 runtime guidance](https://github.com/bhky/opennsfw2)

Use dataset boxes first for panels/bodies/faces. Use the pinned Human-Art detector for additional body proposals, padded 12% on each side and clipped to image bounds. For upper-body proposals use shoulders/hips only when confident; send uncertain truncations to review. COCO17 pose does not provide finger contours or detailed face/foot bounds. Eye/eyebrow/mouth/hand/foot/hair crops are manual in the initial pipeline; automate later only with an independently validated dedicated model. Manually accepted detail crops may be below 256 px at native resolution if their short edge is >= 96 px and the reviewer verifies useful detail; upscaling does not satisfy this gate. Store both original and extraction and reject broken contours/faces/hands rather than masking the defect with a quality score.

### Curation and automatic acceptance

`/curate` supports keep/reject, style/primary/secondary scope, crop editing, person count, SFW decision, malformed anatomy/poor extraction flags, quality 1–3, attribution review, and progress. Quality 1 = unusable; 2 = usable; 3 = strong clean reference. Gold requires explicit keep, quality >= 2, permitted use, and SFW approval. Correcting a crop creates a new derivative/version and invalidates its embeddings/thumbnail/labels pending reprocessing; it never silently edits the live index.

Pilot uses human-approved assets only. After sufficient labels exist, fit a regularized logistic quality classifier on frozen MobileCLIP/DINO features using both kept and rejected **training** items. Use a grouped validation partition for tuning/calibration and a separate untouched quality-audit sample. Predicting 0.9 is not by itself evidence of 90% precision. Choose an automatic-acceptance threshold >= 0.9 on tuning data, then freeze it. Before enabling a style, audit at least 100 predicted-accepted items from at least 30 independent source families of that style, using an untouched validation-source audit partition. Require observed approval precision >= 0.90 and a one-sided 95% lower bound >= 0.90 from 2,000 source-family bootstrap resamples. Report family/item counts and uncertainty; correlated crops are never treated as independent trials. If unavailable/failing, use manual acceptance for that style. An audit used to revise a threshold becomes development data and needs a fresh audit. Never auto-override SFW/provenance rejection.

Record rejected/accepted counts and person-hours. The 2,000-gold goal may require substantially more than 2,000 reviews. Publish a yield/coverage report before expanding beyond the owner-approved pilot effort.

Include viewpoint-axis review, pair-compatibility judgments, and proposal provenance in curation history/snapshots. Crop edits invalidate the crop's viewpoint and usefulness labels as well as its derived embeddings until re-reviewed/reprocessed; a source parent's valid rights record is retained but does not approve the new derivative. Label corrections produce immutable snapshots and a new compatible build rather than mutate an active index. Reviewed ambiguity may remain usable reference material; absent angle labels cannot support an angle-specific claim.

First measure frozen retrieval. The following architecture and hyperparameters are recipes for a later justified, separately authorized experiment; adopting every recipe is not required for delivery or qualification. For adaptation, freeze the text tower and all image modules except the final image stage and projection; also train the new scope head on tight-view embeddings. The registry must list exact trainable parameter names from the pinned model; assert that list at training startup. Keep frozen batch-normalization statistics frozen. Maintain an unreparameterized training checkpoint and a separate validated inference export.

Training defaults: native resolution, AdamW, projection and scope-head LR 1e-4, final-stage LR 1e-5, weight decay 0.01, max 10 epochs, early stop after two epochs without model-selection nDCG@8 improvement, BF16 if forward/backward validated otherwise FP16 with scaling. Set seed 42 and save sampler/RNG/optimizer/scheduler states for resuming.

Loss is `L_InfoNCE + 0.25*L_scope + 0.25*L_consistency`. For each query, InfoNCE is `-log(sum(exp(sim_positive/0.07)) / sum(exp(sim_positive_or_negative/0.07)))` over normalized embeddings, averaged across eligible queries. Positives are annotated usable references; negatives are annotated unusable references or deterministic synthetic negatives with a verified incompatible scope. Unjudged same-subject candidates and known duplicate/alternate-positive pairs are masked out of the negative set. Skip queries lacking a positive or negative and report the skipped fraction. Scope loss is masked binary cross-entropy on reliable prefix labels, with unknown exclusive of known labels. Consistency is cosine distance between two nuisance-augmented views of the **same visible prefix**, not between different completion stages. Thus eye-to-face transitions are not penalized for changing interpretation.

Target optimizer batch 64. Ordinary gradient accumulation does not create 64 contrastive negatives. Use a tested feature-cache/recompute approach across microbatches for the complete 64-example InfoNCE matrix, with correct gradients and fixed BN treatment; if this cannot fit, record the actual negative-pool size and revalidate. [OpenCLIP training implementation](https://github.com/mlfoundations/open_clip/blob/main/src/open_clip_train/train.py)

Optional learned structural projection experiment: frozen DINOv2-small (`facebook/dinov2-small`), pin exact model/preprocessing and 384-dimensional CLS pooling, then `384 -> 512 -> ReLU -> 256` projection and L2 normalization. Use triplet cosine-distance loss, margin 0.2, AdamW LR 1e-4, max 10 epochs, same early-stop rule. Positives are usable paired references; negatives are judged irrelevant same-scope references from training groups. Train projection after semantic adaptation; never mutate the frozen backbone. [Official DINOv2 repository](https://github.com/facebookresearch/dinov2)

### Stroke branch

Input tokens contain normalized x/y, delta x/y, pressure, normalized log delta-time, pen-start/continuation/end marker, layer opacity, and pressure/time availability. Normalize position/delta by 2048. Live vectors retain absolute canvas layout. For QuickDraw/raw external vector sources with arbitrary extents, letterbox their full drawing into a 2048 square with 5% margins before extracting prefixes; record that transform. Synthetic vectors use the same reference-image transform as their paired raster. Never independently rescale each prefix to its own box. Clip time gaps to 1,000 ms and map `log1p(dt)/log1p(1000)`; missing pressure = 0.5/mask false, missing time = 0/mask false.

Preprocessing: retain boundaries and original time/pressure; apply Ramer–Douglas–Peucker tolerance 1 logical px per stroke, then resample at 4-px arc-length intervals. If > 1,024 tokens, increase spacing with deterministic bisection until within budget while retaining each stroke's endpoints/boundaries. If mandatory boundary tokens alone exceed 1,024, disable the branch; never silently drop whole strokes. A single-point tap remains one marked token. Implement matching TypeScript/Python recipes with shared golden fixtures.

Six transformer layers, width 256, eight heads, feed-forward width 1,024, learned positional embeddings for up to 1,024 point tokens plus a CLS token, padding attention masks, CLS pooling, and final projection to the recorded semantic dimension. The transport limit counts point tokens only; model length is at most 1,025 including CLS. Pretrain on raw QuickDraw, using completed QuickDraw raster embeddings as positives and only known category mappings for scope labels. Fine-tune on labeled training sequences and valid synthetic-prefix pairs. AdamW LR 1e-4, weight decay 0.01, max 10 epochs, batch/early-stop rules as above; InfoNCE plus 0.25 same-prefix consistency. Freeze semantic target embeddings while training this branch. Validate missing-pressure/time, erasure-disabled, and long-document cases separately.

### Scope and unknown handling

For a justified learned scope-head experiment, attach an 11-output head to the adapted tight-view semantic embedding. Fit a scalar temperature for independent sigmoid outputs on threshold-selection drawings, and check it on untouched calibration-audit drawings. Unknown has its own labeled examples; lack of a high known probability also permits abstention. Do not interpret independent sigmoid outputs as a probability distribution that must sum to one. A profile retaining frozen text prototypes must validate its own calibration and thresholds before displaying calibrated confidence; it does not require a learned head merely to serve experimentally.

The earlier pilot scope adapter uses frozen text prototypes: three committed prompts per known scope (a line drawing, a sketch, and an ink study of that scope), plus committed unrelated-object/indeterminate-mark prompts for unknown. Normalize the mean embedding per class and apply softmax to tight-view cosine scores divided by 0.07. These are explicitly heuristic scores, not calibrated probabilities. Bootstrap grouping uses known-score >= 0.50, a top-two gap >= 0.15, and unknown < 0.50 for a dominant interpretation; otherwise use known scores >= 0.10 for provisional groups. The pilot UI labels every interpretation experimental and hides percentages. Freeze prompts and defaults in its profile; their replacement by a trained head creates a new build.

Select known-scope confidence, top-two-gap, provisional, and unknown thresholds on threshold-selection data to achieve >= 90% confident scope precision, maximizing coverage among qualifying settings. Search probability cutoffs on {0.05, 0.10, ..., 0.95} and gap cutoffs on {0, 0.05, ..., 0.50}; break ties by higher precision then lower confidence cutoff. Verify the selected rule on untouched calibration-audit drawings and report coverage/sample size. Reusing an audit to change the rule requires a new audit. Provisional mode uses up to three above-floor known scopes when no confident winner qualifies. Exact confidence/gap/unknown cutoffs are serialized in the model bundle. If the calibration sample cannot support a reliable threshold, collect more calibration drawings or keep the affected scopes provisional; never tune on test. Gallery primary scopes determine group membership.

### Pose branch

Begin with the published Human-Art-adapted RTMPose-m and lightweight RTMDet detector, pinning both configurations and hashes, before considering additional fine-tuning. Map Human-Art/Amateur annotations into COCO17 with explicit missing-joint masks; do not treat absent joints as (0,0). Additional adaptation is optional and uses training groups only. Body pose does not replace detail-crop review.

At query time allow detector output of at least nine people so overflow is detectable; if nine or more pass the person threshold, disable pose rather than truncate the composition to eight. Otherwise process at most eight people, with a bootstrap detector threshold 0.5 and >= 6 COCO17 joints per person above 0.5; tune thresholds on model-selection data and freeze before calibration. Precompute gallery skeletons in the same full-image coordinate frame. Pose is unavailable if required detections/keypoints fail, count exceeds eight, or no pair has six mutually visible joints.

Hungarian pair cost uses 0.6 mean joint error after centering/scaling each skeleton by its body box, 0.25 full-canvas centroid error, and 0.15 clipped absolute log height ratio. Clip each component to [0,1]; normalize centroid distance by canvas diagonal and log ratio by log(4). Set any real pair with fewer than six mutually confident joints to cost 1 and treat it as unavailable, and add dummy assignments with cost 1 for unmatched people; divide optimal total cost by max person count. Similarity = 1 - cost. Never mirror a pose or discard left/right labels implicitly. Missing pose is a missing feature, not zero similarity.

Report paired bootstrap uncertainty; this rule is a development choice, not a significance claim. Keep semantic-only, semantic+structure, +stroke, +pose, and calibrated ablations. Every proposed additional branch or learned projection/head, including structure, is conditional on measured benefit. A simpler profile may qualify when it meets the applicable section 2 outcomes and calibration requirements. Missing or failing artifacts required by the selected profile prevent that profile from serving; they do not make another independently validated profile invalid.

For a proposed viewpoint feature, additionally report same/near-view usefulness, wrong-viewpoint distractor errors, ambiguous-prefix behavior, and gallery coverage on the preregistered development slice. Reject apparent subject-only gains that worsen adequately sampled viewpoint cases; do not select on locked-test results. These reporting requirements preserve the existing numeric promotion rule and add no unsupported angle-accuracy claim. Failure to improve justifies a simpler experimental profile or further approved data review, not automatic training or a new mandatory backbone.

## 7. Retrieval, ranking, and runtime reliability

### Views, indexes, and candidates

Normalize query transparency onto white and dark ink to grayscale. Do not automatically invert already line-based drawings; unsupported light-on-dark input is rejected or explicitly normalized by an import tool outside live canvas search. Build full-canvas and tight ink-box views with 10% padding, preserving aspect ratio through letterboxing. Full view preserves canvas-relative layout; tight view supports detail recognition. DINO uses its pinned input transform. Gallery views use exactly the corresponding versioned transforms.

Precompute full/tight semantic vectors, primary/secondary scopes, quality, and duplicate-cluster IDs; add structural vectors and skeletons only for profiles enabling those branches. Query exact top 200 from each available full semantic, tight semantic, structural, and stroke-to-tight-semantic index. Union by stable asset ID, maximum 800 before filtering. Exclude disabled/invalid/unauthorized assets at runtime even if an older index still contains their vectors. Break score ties by stable asset ID.

A style or text hint never adds an image that fails visual relevance. Query scope gates full/tight fusion but never restricts retrieval to a preferred style. For bootstrap fusion, tight weight is 0.8 for eye/eyebrow/mouth/face_head/hair/hand/foot, 0.2 for full_body/multi_character, and 0.5 otherwise; use the highest known-scope prediction only when it passes the provisional threshold, otherwise 0.5.

### Viewpoint compatibility in retrieval

Preserve observable orientation through the existing full/tight views and aspect-preserving transforms. Do not normalize away tilt, silently reflect images, or discard left/right information to raise similarity. Dataset EXIF orientation is corrected consistently before labeling; it is not an angle-invariance rule. Versioned viewpoint metadata and rubric hashes join the gallery/build contract when this capability is implemented.

For identifiable eye queries, ranking must distinguish useful same/near-view structure from reviewed incompatible views. A future query-viewpoint estimate comes from current pixels, not a human evaluation label, assigned-reference metadata, or a manually supplied camera angle. Reference annotations alone cannot infer the query's perspective. Candidate and query uncertainty are masked independently; absent viewpoint is not perfect compatibility, zero visual similarity, or an automatic exclusion of all otherwise useful art.

Keep the existing bootstrap formula as the unvalidated baseline. Any later compatibility feature/filter requires a versioned profile, development validation, and recorded availability/degradation behavior; extend the calibrated ranker's features and missing-value masks rather than silently replacing weights. Only a validated incompatible-view decision can exclude a candidate specifically for viewpoint. A known subject with uncertain angle may return tentative visual matches without a same-angle claim. A confident subject label never upgrades angle confidence.

Apply any validated incompatibility rule before text assistance, duplicate suppression, and diversity selection. Style ordering, optional hints, and maximal marginal relevance cannot reinstate a rejected wrong-viewpoint reference or fill an empty row below the visual floor. If the gallery lacks a useful view, report the coverage limitation and retain no-relevant/provisional behavior as appropriate; do not rotate/generate a substitute, lower the relevance floor, or invent a counterpart. Include CPU and branch-disabled profiles in validation before exposing an angle-specific match label.

### Bootstrap and calibrated ranking

Bootstrap is for development/pilot only. Transform cosine to [0,1] using `(cos+1)/2`. Combine 0.35 semantic fusion, 0.25 structural, 0.20 stroke, 0.20 pose; omit unavailable branches and renormalize **all** active weights. Initial visual floor 0.60 is a versioned engineering default to tune on pilot labels, not a calibrated probability. Display qualitative match labels only.

For validated v1, fit L2-regularized logistic regression to human pair labels, target grade >= 2. Features: full/tight/structural/stroke cosine, pose and availability, scope compatibility, person-count compatibility, query/candidate ink occupancy, quality probability, native/extracted flag, log1p source stroke/point counts, their approximation mask, plus every feature's availability mask. Scope compatibility is the maximum query probability among candidate scope labels; person compatibility is `1 - min(abs(q-c)/max(q,c,1),1)` when both counts are known. Counts summarize the current source operations with the stated approximation mask, never future completion percentage. Human approval and predicted quality remain distinct fields; an unavailable quality-model output is masked, not assigned a fictitious probability of 1.

Collect at least 2,000 judged training pairs from >= 100 distinct training prefixes and 1,000 held-out development/calibration pairs (at least 300 model-selection, 300 threshold-selection, and 400 calibration-audit), covering every scope/style plus easy/near negatives, provisional inputs, and branch-disabled profiles. Candidate pools include frozen baseline, bootstrap, ablations, and random same-scope candidates. Do not label unjudged pairs negative. Keep all pairs from a drawing/source group together. Use train-only feature means/scales; missing continuous features become the train mean (zero after scaling), with masks. Use grouped cross-validation on training pairs to select C from {0.01, 0.1, 1, 10}. Retrain on training pairs, select operating thresholds on threshold-selection drawings, and measure reliability/precision/coverage on untouched calibration-audit drawings by feature profile. Record whether counts are too sparse to support a claim.

The calibrated visual probability `p` is eligibility. On threshold-selection data, search thresholds {0.50, 0.51, ..., 0.99} and choose the smallest achieving >= 90% observed relevance precision and section 2's coverage target; break ties by greater coverage. Freeze that threshold, then require the same coverage plus observed precision >= 0.90 and a one-sided 95% lower bound >= 0.90 on the untouched calibration audit, using 2,000 bootstrap resamples of complete drawings. The audit needs at least 20 independent drawings and 100 displayed query/asset pairs per enabled profile; point/prefix pairs are not independent trials. An audit that informs retuning must be retired and replaced. If no threshold qualifies, gather more labels/improve retrieval instead of claiming calibration. Require separate validated thresholds or evidence for CPU/pose-disabled/stroke-disabled profiles. Thresholds and feature preprocessing are immutable build artifacts.

Optional text is an assisting hint: only after the visual floor, rank by `0.9*p + 0.1*t`, where `t = (cos(text, gallery_tight_semantic)+1)/2`; without text rank by `p`. In the pilot, substitute the bootstrap visual score for p and retain its uncalibrated label. Report visual relevance separately from final ranking score. Do not pass selected style into this score. Benchmark default search with empty text, plus a separate fixed-hint experiment. A hint cannot rescue a visually ineligible candidate.

Suppress members of the same confirmed duplicate cluster within each group. Best Match then uses maximal marginal relevance: `0.85*rank_score - 0.15*max_redundancy`, where redundancy is normalized tight-semantic cosine to an already selected result (zero for an empty selected set). Style rows take the top six eligible ranked assets of that style with duplicate suppression. Provisional groups restrict to candidate primary scope matching the interpretation and use the same visual eligibility floor; omit empty groups. If no group survives, return insufficient with reason `no_relevant_candidates`.

### Scheduling and cancellation

One inference executor runs at most one job. Each session has at most one replaceable pending job; globally permit at most four pending sessions, scheduled round-robin. A newer generation replaces the session's pending job; superseded waiting callers get a structured 409. Extra sessions receive 429 with Retry-After. Expire idle scheduling state after 30 minutes. A new UUID is required if a client exhausts safe generation integers.

Track latest generation per session before queueing and recheck before preprocessing, inference branches, reranking, and response publication. Disconnection/abort marks work obsolete. Running CUDA kernels may complete; cancellation is cooperative and must not release the executor while kernels still use model buffers. Discard output from obsolete work. Deadline is measured from request receipt: 2 seconds in GPU mode, 10 in CPU mode; an event-loop timer returns 504 to a still-connected HTTP waiter at the deadline and marks its job obsolete. The inference executor remains occupied until active work safely completes; its result is discarded. Phase checks avoid starting more expensive work after expiration, and no next GPU job starts while prior kernels still use shared buffers.

The health/events handlers remain responsive while inference runs. Avoid per-request model loading, unbounded threads, and parallel GPU jobs. Cache gallery thumbnails; retain no user-query cache across sessions by default. Reject every generation <= the latest accepted generation for that session with 409, even when content matches. An explicit Retry always uses a fresh generation; search has no same-generation retry cache.

### Startup, failure, and recovery

Startup validates configuration, DB migrations, manifest/index/model compatibility, permitted enabled assets, and model warmup. Missing mandatory artifacts leaves liveness/setup routes available but readiness false and search returns 503. The canvas can still draw/export. Fixture mode is explicit and clearly labeled.

CPU mode uses FP32 inference for the selected encoder/scope profile and CPU indexes, with stroke/pose disabled initially. Load a ranking bundle validated for this profile. If no validated CPU calibration exists, label results provisional/experimental rather than display calibrated confidence. Training is unsupported in CPU mode. Missing optional pose/stroke artifacts disable their branches and use the matching profile; missing mandatory artifacts do not silently become valid fixture results.

On CUDA OOM: mark obsolete pending jobs, let active work unwind, release failed tensors, collect unused allocations, clear cache, and retry the current query once with pose disabled and its ranking profile. If OOM repeats or a mandatory model cannot fit, unload GPU models, enter a controlled not-ready state, load CPU models/profile, warm, and resume. A failed CPU reload leaves readiness false and explains recovery. Never claim `empty_cache()` frees live weights or repeatedly retry the same impossible allocation.

Corrupt/missing assets are disabled and omitted immediately. Out-of-space ingestion/index builds abort staging without touching the active build. SQLite writes use short transactions and bounded retry for busy errors; API errors never report an event/pin saved before commit. Back up metadata before migrations; rollback includes compatible DB schema and artifact pointers. Provide documented backup/restore commands for metadata, labels, and user-exported documents.

### Local documents and portable schema

Section 4's drawing-operation and `.drawable` v1 contracts are public compatibility surfaces. Import parsing, structural validation, asset checksum verification, and size/capacity validation complete before one transaction materializes a new document. Pydantic specifies health/readiness, curation, and the bounded multipart search request. The search route enforces the body, image, gzip, and token limits below, validates preprocessing versions, rejects stale generations, returns 200 for independently detected insufficient ink, and returns 503 for a sufficient query until approved serving artifacts and a bounded inference executor exist. The complete ranked search response and the preferences, assets, events, and gallery-build contracts remain target work. ### Common API rules

Pydantic/OpenAPI is the contract source of truth. All JSON responses include schema version and a request ID; binary asset responses use corresponding response headers. Structured errors are `{schema_version, error: {code, message, retryable, details}, request_id}` and never include absolute file paths or stack traces. Unknown fields are rejected on mutation bodies. All floats must be finite. URLs exposed to the UI are same-origin asset-ID routes, never local paths.

One server-local profile stores explicit style, learning flag, affinities, and pins. `document_id` identifies persistent browser artwork; `session_id` identifies one runtime tab's query sequence. These are not accounts or authentication identities. Pin/preferences persist across drawings; drawing-session reset does not reset preferences. Fixture data uses a separate DB and IndexedDB namespace.

### `POST /api/v1/search`

Multipart form fields:

| Field | Validation |
| --- | --- |
| `session_id`, `document_id` | UUIDs |
| `canvas_revision`, `query_generation` | Integers 0..2^53-1; generation must increase for new work |
| `canvas_width`, `canvas_height` | Exactly 2048 each in v1 |
| `stroke_count`, `point_count` | Source draw-operation/raw-point counts defined in section 4; 0..10,000 and 0..1,000,000 |
| `counts_approximate` | Boolean; true when erases or outside paths make source counts differ from visible ink |
| `image` | PNG, <= 4 MiB compressed, decoded exactly 512 × 512, RGB/RGBA/grayscale/grayscale-alpha supported |
| `strokes` | Optional gzip JSON file; <= 256 KiB compressed and <= 1 MiB decompressed; strict schema and <= 1,024 tokens |
| `stroke_status` | `available`, `too_short`, `erased_layers`, `raster_content`, `unsupported_transform`, `out_of_bounds`, `too_many_boundaries`, or `disabled` |
| `preprocessing_version` | Must match the active recipe; otherwise 409 requiring frontend refresh |
| `text_hint` | Optional normalized string <= 120 Unicode code points |

The parser accepts at most 16 unique multipart fields and rejects preambles, epilogues, duplicate names, unknown fields, and invalid boundary framing before MIME part decoding. Content length and streamed body bytes are each checked against the 5 MiB cap. The active `drawable-query-v1` blank-input rule composites alpha over white, converts to grayscale, counts pixels below intensity 245, and returns `insufficient_visible_ink` when fewer than eight such pixels exist or their bounding-box diagonal is under three pixels. This is only an input sufficiency check; it does not call a model or infer a subject.

The stroke JSON includes schema/version, token count, boundary markers, normalized positions/deltas, pressure/time/opacity and masks. Available sequence positions are normalized to [0,1] after eligibility checks, never independently clamped from outside coordinates. Pressure/opacity are in [0,1]; deltas agree with successive positions within 1e-5, and deltas reset to zero at stroke start. Gzip uses bounded streaming decompression; reject nested/concatenated gzip, invalid UTF-8/JSON, unsupported token fields, nonfinite values, contradictory counts/status, and invalid normalized time deltas (finite [0,1], zero at each stroke start). The wire format has no absolute timestamps, so absolute monotonicity is checked when building the document/payload, not invented by the server. An unavailable stroke status, including `raster_content`, requires the strokes field to be omitted; available requires 20–1,024 point tokens with valid boundaries. `stroke_count` and `point_count` describe vector draw/erase sources only; raster operations remain represented in the image and document-capacity accounting. Total HTTP body limit 5 MiB is enforced before full buffering. The server independently calculates raster sufficiency; client counts never override it. Selected style is intentionally absent because it only changes row order.

Once the approved inference executor is installed, a sufficient query's successful response includes:

- Echoed session/document/revision/generation; request ID; build/model/preprocessing versions.
- `mode`: insufficient/provisional/confident; machine-readable reason and warnings.
- Ordered known/unknown scope scores and scope-calibration status.
- `groups`: stable ID, title, style or known scope, results. Group/result maximum counts follow section 4.
- Each result: asset ID, local thumbnail/full/detail routes, style/scopes, native/extracted flag, visual relevance (nullable if uncalibrated), match label, quality, trace permission, attribution summary.
- Availability of semantic/structural/stroke/pose/text features and degradation reasons.
- Server timings: queue/preprocessing/embedding/retrieval/reranking/total ms. GPU phase timings synchronize appropriately; frontend records snapshot/upload/decode/paint separately.

When viewpoint support is implemented, add schema-versioned query viewpoint/availability and per-result match-status metadata separately from scope confidence and calibrated visual relevance. Expose only supported qualitative interpretations and degradation reasons; unknown or experimental estimates never become precise camera-angle claims. The existing multipart request remains sufficient: the server derives any query estimate from visible artwork, and no client-supplied evaluation labels or assigned-reference viewpoint may act as ground truth. Keep inference-only query estimates ephemeral under the existing privacy policy. The current API shell does not implement these response extensions.

Blank/insufficient input returns 200 with no dynamic groups. The current response marks all feature branches unavailable, includes echoed identifiers and preprocessing version, and never starts training or uploads data. Malformed multipart, undecodable images, and invalid gzip return 400; a decodable image with wrong format/dimensions/mode returns 422. Oversized body/image/compressed/decompressed payload returns 413; other schema errors return 422; superseded/version-conflict returns 409; capacity returns retryable 429; sufficient input without approved serving artifacts returns 503; inference deadline returns 504 once the bounded executor is implemented. A client ignores obsolete 409s; other errors preserve prior results as described in section 4.

### Assets and provenance

`GET /api/v1/assets/{asset_id}/thumbnail`, `/image`, and `/metadata` validate stable IDs, active enabled status, permitted use, and canonical paths beneath approved asset roots. Prevent traversal/symlink escape. A disabled asset returns 404 even through an old pin. Use immutable build/checksum ETags for eligible images; do not serve source directories or user files. Metadata includes attribution and use constraints. Pins to withdrawn assets show “Unavailable” and can be removed.

Planned detail metadata includes reviewed viewpoint attributes, annotation/rubric version, evidence basis, and crop-to-parent context identity when available. A parent/context image is served only through the same asset-ID and permission checks; a crop's permission does not automatically permit its entire source panel. Missing or withdrawn context does not trigger remote fetching or bypass unavailable-asset behavior. Reviewed candidate metadata is not a confidence score for its match to the current query.

### Preferences, events, and pins

`GET /api/v1/preferences` returns explicit style or null, learning enabled, affinities, preference version, and ordered styles. `PUT` accepts explicit style/null, learning enabled, or a reset-learned action. Changes are atomic. Reset clears learned interaction history/aggregates, preserving explicit style and pins; “reset all preferences” is a separate explicit UI action.

`POST /api/v1/events` accepts `event_id` UUID, session ID, asset ID, event `open|pin|unpin|trace`, query generation/revision, and optional response request ID. The server supplies timestamp and derives style from asset metadata; clients cannot spoof style. Duplicate event IDs return the original outcome without double counting. Trace/open events record completed user actions, not hover or failed loading. Pin/unpin mutate the persisted pin set in the same transaction as the event; repeated pin on an already pinned asset adds no learning weight. `GET /api/v1/pins` lists pins in most-recently-pinned order with asset availability. Document undo of trace does not undo historical interaction learning.

Event weights: open 1, pin 3, trace 4, unpin 0. At server time t, `C_style = sum(weight*2^(-(t-event_time)/30 days))`, and affinity = `(1+C_style)/(5+sum(C))`. Fixed style order breaks exact ties. Disabling learning freezes affinity updates/decay for ordering by using the fixed default order, preserves prior data, and records only pin mutations, not affinity events. On re-enable, retained old events decay using elapsed wall time. Prune ordinary event detail after 180 days while preserving equivalent decayed aggregate contributions; a reset removes both. Limit open/trace learning to one event per asset/action/generation to prevent repeated clicks from dominating. Preferences never alter visual floors, candidate recall, or Best Match.

### Health and curation

`GET /api/v1/health` always returns liveness, readiness, fixture/CPU/CUDA mode, GPU name/VRAM, model/build IDs, gallery size, enabled branches, warmup, and setup errors. `GET /api/v1/ready` returns 200 only when mandatory serving artifacts are ready, otherwise 503. No private paths or image contents appear in either response. The current review-only implementation exposes candidate listing, permission-gated preview, progress, the versioned viewpoint rubric, review/history, crop creation, pairwise asset-to-asset view-match recording, and immutable review-snapshot creation. Mutations are disabled unless `CURATION_MODE=1`, reject unapproved browser origins, use optimistic asset revisions/idempotency keys, and do not expose locked-test assets or local filesystem paths. Query-prefix/pairwise challenge review, an immutable gallery-build/activation pipeline, production same-origin packaging, and approved-candidate evidence remain required.

### Metrics and contamination policy

- Precision@k: number of grades >= 2 divided by fixed k, missing slots zero; macro mean over queries.
- DCG@8: sum `(2^grade - 1)/log2(rank+1)`; IDCG sorts the **same common judged pool**. Name the metric pooled nDCG@8 because relevance outside the pool is unknown. IDCG=0 contributes zero and is counted/reported separately; dataset-wide usefulness cannot be inferred from this pool alone.
- MRR@8: inverse rank of first grade >= 2, zero if none.
- Scope: top-one/top-three hit rate against prefix acceptable scopes, plus multi-label recall, calibration/reliability, and unknown false-confidence rate.
- Confident error: grade-0 fraction of displayed confident occurrences, with duplicate cross-row appearances counted as exposures; also report unique-query/asset error.
- Coverage: confident-query fraction, returned-slot fraction, provisional/insufficient rates, and percentage receiving >= 4 useful results.
- Stability: adjacent-stage Jaccard overlap of result IDs and scope transition/convergence rate; report, do not maximize overlap when scope legitimately changes.
- Breakdowns: stage, primary visible scope, requested task style, candidate style, multi-character, native/extracted, missing branches, and CPU/CUDA mode. Show counts and label sparse cells descriptive.
- Timing: p50/p95 and failures/cancellations under section 2's protocol, with each stage and peak memory recorded.

Report paired 95% bootstrap intervals with 2,000 resamples of whole drawing sequences, retaining all their prefixes together. The primary release gates use the preregistered point estimates; intervals show uncertainty, not extra unstated gates. Do not claim broad per-style generalization from a small sample.

Run the locked test once after model/threshold/gallery freeze and validation gates pass. If results inform a change, retire that holdout to historical regression status and collect a new independent holdout for a fresh confirmatory claim. Merely versioning another model does not make reuse independent. A rerun solely to correct an evaluation-code defect must disclose the defect, unchanged artifacts, and every prior result. Never train/tune thresholds from test outcomes or selectively report a better run.

### Research and implementation decision rules

- Insufficient permitted gallery yield: add another eligible source or project-created references; report coverage gaps. Never fabricate image availability or relax review silently.
- Insufficient same/near-view coverage: measure supported and missing angles, prioritize reviewed eligible sources within the approved budget, and retain tentative/no-match behavior. More correlated frames, mirrored copies, or synthetic warps do not establish independent viewpoint coverage. Do not certify angle matching by excluding uncovered identifiable queries.
- Insufficient human time: stop at the current measured stage, report partial counts and outstanding work, and expand only when the owner budgets more participation. Completing prototype or pilot targets is not required before stopping.
- No benefit from a proposed encoder: retain the validated simpler profile; do not implement complexity merely because it appeared in the original architecture.
- No measured benefit from detail/viewpoint automation or fine-tuning: retain reviewed manual preparation and the simpler frozen experimental baseline. Do not describe generic embeddings, body keypoints, or training completed elsewhere as validated eye-angle recognition.
- No threshold meets precision and coverage together: improve data/model or retain experimental status; a high threshold with almost no results is not success.
- Hardware gate fails: diagnose driver/runtime/model compatibility and benchmark lower-cost profiles; no claim of RTX performance until measured.
- Benchmark baseline is too strong for a 20% relative gain: record the mathematical limitation and obtain an explicit revised research target before making the claim, rather than manipulating the baseline.

Full validated research completion means working software, reproducible artifacts, source access for the used data, passed engineering checks, and an honestly evaluated result. The plan resolves implementation choices while keeping unmeasured research outcomes visible as gated work.

### Catalog, search, and release safety

V2 supports up to 10,000 prototype entries while V1 snapshots/builds remain readable. Typed provenance records `human`, `assistant`, or `local_model`, reviewer/profile, evidence, model/runtime hashes, prompt/rubric, run, image hash, and reviewed revision. V2 assigns no research split. Keep the current frozen MobileCLIP CPU retrieval baseline. Compare DINO only on development queries if measured usefulness justifies its extra branch. Use exact ranking at 500 and 1,000 entries unless measurements show it is inadequate.

Staging builds are validated before atomic activation. Build-specific previews remain stable, a running worker remains on its startup build, and rollback validates a retired build before switching the active pointer. A content-addressed availability mask removes withdrawn, stale-revision, changed, or corrupt items from search and preview without waiting for another full index build. Invalid masks fail closed for V2.

Search keeps Best Match first and returns up to six groups with four cards each. Style preference reorders real provisional results. Rows avoid repeated canonical assets, root images, clips, and sources while keeping match relevance ahead of variety. Thumbnails lazy-load. Reference labels describe the reference only; they are not recognition claims about the user's drawing or calibrated confidence.

Repeating an already committed import returns its existing run without creating reviews or assets. Qualification or finalization remains explicitly awaiting review until those files contain complete, schema-valid assistant judgments. Before resuming local-model qualification, persist per-image and per-model checkpoints so interruption can resume without discarding completed work.
